# Data Snapshot and Catalog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `python -m martian_map snapshot`. It downloads or computes every *local* dataset for the Gale data-center site study into `data/`, and writes a committed `data/catalog.json` that indexes every source (local, live, not used) with the project plan's evidence labels.

**Architecture:**
- **Fetching:** one polite HTTP fetcher with a host allowlist, rate limit, size caps and atomic writes.
- **Steps:** each data source is a small step module that returns catalog entries. An orchestrator runs the steps, records failures and writes the catalog.
- **Assumptions:** they live in the hand-edited `scenario/gale.json`.
- **Computed layers:** slope, roughness, horizons and sun tables are pure numpy functions, tested on synthetic data.

**Tech Stack:** Python 3.9, numpy (new), requests (existing), pytest with the existing `FakeSession`/`FakeResponse` in `tests/conftest.py`.

**Spec:** `docs/superpowers/specs/2026-11-14-data-snapshot-design.md` (approved revision 2). Also read
`docs/PROJECT_PLAN.md`, the team plan the spec serves, and `docs/data-extraction.md`, which has the
live-verified endpoint details. Executors read all three.

## Global Constraints

- Python `>=3.9`. The only new dependency is `numpy>=1.22,<2.1` (2.0.x is the last line that supports 3.9). Don't add scipy, Pillow, rasterio or GDAL.
- Every HTTP request:
  - goes through `martian_map.http.Fetcher`: HTTPS only, allowlisted hosts, `allow_redirects=False`, timeout, byte cap, TLS verification on (requests' default; never pass `verify=False`);
  - is rate-limited to ≥1.0 s between requests to the same host;
  - must never hit Trek `data/stream` (the URL denylist contains `/data/stream`).
- **Evidence labels:** every catalog entry has `evidence_type` ∈ {observation, derived, model, interpretation, assumption, reference}, a single value, plus an optional `evidence_note`.
- **`factors[]`** ⊆ {terrain, ground, solar, thermal, routes}.
- **`access`** ∈ {local, live, computed, not_used, pending}. Files we write use `local`; `computed` stays a valid value but no step emits it.
- **`status`** ∈ {ok, failed, not_downloaded}.
- **No thresholds or good/bad classes in data.** Slope is in degrees and roughness in metres. Thresholds exist only as placeholders in `scenario/gale.json`.
- **Missing data is NaN** (or a recorded nodata value), never 0. Overlays draw nodata transparent.
- **Grid files** are raw little-endian (`.f32` float32, `.u8` uint8). Row 0 is the north edge. Bounds are `[W, S, E, N]` in degrees east and planetocentric latitude, with `crs` `"IAU Mars 2000 sphere r=3396190 m, equirectangular (Esri wkid 104905)"`.
- **Mars sphere radius for terrain maths:** `3_396_190.0` m. `geo.py` keeps its own `3389.5` km mean radius; don't change it.
- **The catalog is generated, never hand-edited.** Its top-level `_note` reads exactly: `"Generated by python -m martian_map snapshot. Do not edit by hand; edit scenario/gale.json or the step code instead."`
- **Git:**
  - `data/` stays ignored except `data/.gitkeep`, `data/README.md` and `data/catalog.json`;
  - `scenario/gale.json` is committed;
  - no API key or token in any committed file or in `data/`;
  - work on branch `feat/data-snapshot`, never push.
- **Every file a step writes goes through `http.atomic_write`** (or writes to a `.part` path and then `os.replace`), so an interrupted run never leaves a half-written file.
- **Docs:** plain language for a non-expert. Explain every technical term at first use or in the glossary.

## Review Focus

1. **NaN / nodata at grid edges and holes.** A missing elevation must become NaN slope, NaN roughness and a transparent overlay pixel, never "0° = flat". *(Test: Task 6 `test_slope_nan_propagates`, Task 5 `test_overlay_nodata_transparent`.)*
2. **HTTP 200 carrying an error body.** That means ArcGIS `{"error": …}`, an HTML page where JSON was expected, or a too-short binary export. It must fail the step, never be saved as data. *(Tests: Task 1 `test_get_json_rejects_html`, Task 8 `test_arcgis_error_object_fails`, Task 5 `test_bsq_wrong_length_rejected`, Task 7 `test_bsq_wrong_length_rejected_in_step`.)*
3. **A run interrupted mid-download, then re-run.** No half-written file may pass the freshness check. *(Tests: Task 1 `test_atomic_write_leaves_no_partial`, Task 4 `test_is_fresh_false_on_hash_mismatch`.)*
4. **A scenario site outside the 1 m elevation area or in a no-data hole.** That's a clear error or warning, never an empty grid. *(Tests: Task 2 `test_site_outside_study_area_rejected`, Task 7 `test_low_coverage_site_warns`.)*
5. **`catalog check` on a fresh clone with no `data/` files.** It reports "not downloaded" and exits 0, or 1 with `--strict`. *(Test: Task 4 `test_cli_catalog_check_fresh_clone`.)*

### Task 1: Polite fetcher

**Files:**
- Create: `src/martian_map/http.py`
- Test: `tests/test_http.py`
- Modify: `requirements.txt`, `pyproject.toml` (add `numpy>=1.22,<2.1`)

**Interfaces:**
- Produces:
  - `class FetchError(RuntimeError)`.
  - `DEFAULT_ALLOWED_HOSTS: frozenset = {"trek.nasa.gov", "mars.nasa.gov", "services.arcgis.com", "oderest.rsl.wustl.edu", "stac.astrogeology.usgs.gov", "swim.psi.edu", "www-mars.lmd.jussieu.fr"}`.
  - `DENY_SUBSTRINGS = ("/data/stream",)`.

    - `.get_bytes(url: str, max_bytes: int) -> FetchResult`, where `FetchResult(body: bytes, content_type: str, url: str)`;
    - `.get_json(url: str, max_bytes: int = 50 * 2**20) -> Any`.

### Task 4: Snapshot orchestrator, static entries and CLI (the index ships here)

**Files:**
- Create: `src/martian_map/snapshot.py`, `src/martian_map/sources/__init__.py`, `src/martian_map/sources/static.py`
- Modify: `src/martian_map/cli.py` (add `snapshot` and `catalog` subcommands; catch `FetchError` like `TrekError`)
- Test: `tests/test_snapshot.py`, `tests/test_cli_snapshot.py`

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces:
  - `@dataclass StepContext(scenario, data_root: Path, fetcher: Fetcher, refresh: bool, previous: Optional[Catalog], log: Callable[[str], None])`, with:
    - `.path(rel) -> Path` (creates parents);
    - `.is_fresh(entry_id) -> bool`: True only when `previous` has this entry with status ok and every file's bytes and sha256 match on disk, and `refresh` is False.
  - `@dataclass(frozen=True) Step(id: str, dataset_ids: Tuple[str, ...], run: Callable[[StepContext], List[Dict]], stretch: bool = False)`.
  - `run_snapshot(scenario, data_root, fetcher, only: Optional[Set[str]] = None, refresh=False, include_stretch=False, log=print) -> SnapshotReport`, where `SnapshotReport(catalog, failed: List[Tuple[str, str]], warnings: List[str])`.
    1. Load the previous catalog if one exists.
    2. Run each selected step. `only` matches a step id or any of its dataset_ids. A step is skipped, keeping its previous entries unchanged, only when every one of its dataset_ids is fresh. Steps with no dataset_ids always run (they update other entries, for example alignment).
    3. If a step raises, upsert an entry per dataset id with `status="failed"`, `error=str(exc)`, the previous entry's descriptive fields if any, otherwise a minimal one. Then continue.
    4. Entries from unselected steps carry over.
    5. Fill `areas` from the scenario. Build `coverage_report` with `build_coverage_report`, then save to `data_root/"catalog.json"`.
  - `build_coverage_report(catalog, scenario) -> List[Dict]` gives one row per (area ∈ study_area + each site) × (entry with `access` ∈ {local, live}), as `{area, dataset_id, covers: "full"|"partial"|"none"|"unknown", covered_fraction, resolution_m}`.
    - **Grid entries:** use the entry's own `coverage.covered_fraction` when its area is the row's area.
    - **Otherwise:** compare `coverage.bounds` with the area: the area is inside → full; they intersect → partial; no overlap → none; no bounds → unknown.
  - `sources.all_steps(scenario) -> List[Step]` in the spec's build order. Later tasks append to it.
  - `static.static_entries(scenario) -> List[Dict]` and the step `static_step` (id `static`).
  - CLI:
    - `snapshot [--only ID[,ID]] [--refresh] [--stretch] [--data-root data] [--scenario scenario/gale.json]` exits 0, or 1 if anything failed;
    - `catalog check [--strict]`, `catalog search WORDS... [--factor F]`, `catalog table [--write PATH]`.

  - `solar_declination_deg(ls_deg) -> float` = `degrees(asin(0.42565*sin(Ls))) + 0.25*sin(Ls)` (Mars24, Allison & McEwen 2000, eq. D-5).
  - `sun_elevation_azimuth(lat_deg, ls_deg, ltst_h) -> Tuple[float, float]`: hour angle `15°*(ltst_h - 12)`, azimuth from north clockwise, `ltst_h` in Mars hours.
  - `sun_table(lat_deg, ls_step=15.0, time_step_h=0.5) -> Dict` → `{"ls": [0..345], "ltst_h": [0.0..23.5], "elevation_deg": [[...]], "azimuth_deg": [[...]]}`.
  - `sunlit_fraction(table, horizon_deg: np.ndarray (n_points, 360)) -> List[List[float]]`: the fraction of points with `sun_el > horizon[round(az) % 360]`, and 0 when `sun_el <= 0`.
  - Step `solar_<site>`, with datasets `horizon_<site>` and `sun_table_<site>`:
    - writes `data/solar/horizon_<site>.u8` (grid meta plus `azimuth_count: 360`, `step_deg: 0.25`) and `data/solar/sun_table_<site>.json` (the table plus `sunlit_fraction`);
    - evidence: horizon `derived`, sun table `model` with `evidence_note` "sun position from a standard formula; shadows from derived elevation";
